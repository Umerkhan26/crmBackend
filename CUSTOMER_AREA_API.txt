================================================================================
CUSTOMER AREA + CUSTOMER ACCOUNTS — API REFERENCE
Base: {API_HOST}/api
================================================================================

ONE backend (crmBackend) for xCRM staff + customer portal apps.
Separate portal project = customer frontend only (deploy later on customer.* domains).

--- HOW IT WORKS ---

On sale submit, backend creates:
  1. users row (email + password, userrole = customer)
  2. customer_accounts row (links user + lead + sale + optional brand)

Portal app logs in via /api/customer-area/login.

--- SETUP (once, in crmBackend folder) ---

  npm run sync:customer-area
  npm run seed:customer-role
  npx ts-node src/scripts/seed-portal-brands.ts

  .env (backend, for local portal dev):
    CUSTOMER_PORTAL_LOCAL_BRAND_SLUG=emrills
    CUSTOMER_PORTAL_URL=http://localhost:3100
    CORS_ORIGINS=http://localhost:3100,http://localhost:5173

  Resolve brand on localhost using ANY of:
    ?brandSlug=emrills | ?brandId=1 | ?portalHost=customer.emrills.com
    Header: x-customer-host: customer.emrills.com

  Production: host customer.emrills.com resolves brand via brands.subdomain

================================================================================
xCRM STAFF APIs
================================================================================

POST /convertLeadToSale
  Create sale + auto-create customer account (default).
  Body: { leadId, campaignId, assigneeId, products OR productType+price,
          brandId (optional), autoProvisionCustomer (optional, default true) }
  Response: customerProvisioning { provisioned, emailSent, userId, reason }

GET /customer-accounts?page=1&limit=10&search=&brandId=
  List all customer accounts. Auth: Staff JWT + customerAccount:get

GET /customer-accounts/:id
  One customer with user, brand, lead, sale. Auth: customerAccount:get

GET /customer-accounts/:id/insights
  Emails, engagements, timeline. Auth: customerAccount:get

POST /customer-accounts/:id/send-email | /upsell | /discount | /notify
  Customer engagement actions. Auth: customerAccount:create

POST /customer-accounts/provision-from-sale/:saleId
  Retry account creation for existing sale. Body: { brandId? }

GET /brands/portal/list
  Brands for agent selector (GWB, Emrills, Dnova). Auth: brand:get

GET /brands/portal/:brandId/sales-form
  Sales form config per brand. Auth: brand:get

GET /getleadByid/:id
  Load lead on sales form (existing endpoint).

Portal content (staff JWT + portalContent:* permission):
GET    /portal-content/brands
GET    /portal-content/announcements?brandId=
POST   /portal-content/announcements
PATCH  /portal-content/announcements/:id
DELETE /portal-content/announcements/:id
GET    /portal-content/popups?brandId=
POST   /portal-content/popups
PATCH  /portal-content/popups/:id
DELETE /portal-content/popups/:id
PATCH  /portal-content/sales/:saleId/progress
       Body: { label, percent, steps: [{ name, done }] }

CUSTOMER PORTAL APIs (separate app — customer JWT)
================================================================================

GET  /customer-area/resolve-brand?brandSlug=emrills
GET  /customer-area/brand-config          (same; theme, logo, colors)
POST /customer-area/login

GET  /customer-area/me
GET  /customer-area/stats                 (dashboard counts)
GET  /customer-area/my-sales              (legacy summary)
GET  /customer-area/orders
GET  /customer-area/orders/:saleId/progress
GET  /customer-area/invoices
GET  /customer-area/offers
GET  /customer-area/announcements
GET  /customer-area/popups
POST /customer-area/popups/:popupId/dismiss
GET  /customer-area/notifications

Auth: Authorization: Bearer <customer token>
Brand (local): JWT brandId OR ?brandSlug= OR x-customer-host

Brand theme in DB: brands.salesFormConfig.portalTheme
  { logoUrl, primaryColor, supportEmail, supportPhone }
