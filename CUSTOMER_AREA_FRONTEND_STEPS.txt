================================================================================
CUSTOMER AREA PORTAL — FRONTEND DEVELOPER GUIDE
================================================================================
Base URL: {API_HOST}/api/customer-area
Example local: http://localhost:3000/api/customer-area

Separate app (NOT Crm-Frontend). One shared backend (crmBackend) — no second API server.

================================================================================
STEP 0 — BACKEND MUST BE READY FIRST (backend team / you on crmBackend folder)
================================================================================
Run these in order from project root: d:\crmBackend (or /home/backendCrm/crmBackend on server).
Frontend will NOT work until these are done and API is running.

0.1  | cd crmBackend
     | Open the backend project folder.

0.2  | npm install
     | Install Node dependencies (first time only).

0.3  | Configure .env (backend)
     | Set DB_NAME, DB_USER, DB_PASS, DB_HOST, PORT=3000, JWT_SECRET, SMTP for emails.
     | For customer portal local dev, backend should also add:
     |   CUSTOMER_PORTAL_LOCAL_BRAND_SLUG=emrills
     |   CORS_ORIGINS=http://localhost:3100,http://localhost:5173
     |   CUSTOMER_PORTAL_URL=http://localhost:3100

0.4  | npm run sync:customer-area
     | Creates/updates DB tables: customer_accounts, portal_announcements, portal_popups, etc.

0.5  | npm run seed:customer-role
     | Creates customer role + permissions in DB (required for login).

0.6  | npx ts-node src/scripts/seed-portal-brands.ts
     | Seeds GWB, Emrills, Dnova brands with slug/subdomain for portal.

0.7  | npm start
     | Starts API server (default http://localhost:3000). Keep it running while you develop.

0.8  | Verify API is up
     | Open browser or curl: GET http://localhost:3000/api/customer-area/brand-config?brandSlug=emrills
     | Expect: { "success": true, "data": { "name": "Emrills", ... } }

0.9  | Create a test customer (if none exists)
     | Customer accounts are NOT created from portal — agent must submit a sale in xCRM
     | (POST /api/convertLeadToSale) OR backend runs provision-from-sale for an existing sale.
     | Customer receives welcome email with email + password — use that to test login.

================================================================================
STEP 1 — FRONTEND PROJECT SETUP (your new portal app)
================================================================================
1.1  | Create new frontend repo (React / Next / Vite — not Crm-Frontend).
1.2  | Add .env: VITE_API_URL=http://localhost:3000/api  (or REACT_APP_API_URL).
1.3  | Add .env: VITE_DEFAULT_BRAND_SLUG=emrills  (used on every API call in local dev).
1.4  | Add .env: VITE_CUSTOMER_HOST=customer.emrills.com  (optional header x-customer-host).
1.5  | Confirm backend added your dev URL to CORS_ORIGINS (e.g. http://localhost:3100).
1.6  | npm install && npm run dev  — start your portal on port 3100 or 5173.

================================================================================
STEP 2 — FIRST API CALLS TO BUILD (order)
================================================================================
2.1  | On app load → GET /customer-area/brand-config?brandSlug=emrills  (theme, logo).
2.2  | Login page → POST /customer-area/login?brandSlug=emrills  (save token).
2.3  | After login → GET /customer-area/stats?brandSlug=emrills  (dashboard cards).
2.4  | Then build other pages using endpoint list below.

================================================================================
BRAND ON EVERY REQUEST (REQUIRED FOR MOST ROUTES)
================================================================================
Local dev — use ONE of these on every call:
  Query:   ?brandSlug=emrills
  Query:   ?brandId=1
  Query:   ?portalHost=customer.emrills.com
  Header:  x-customer-host: customer.emrills.com

Production: host customer.emrills.com resolves brand automatically (no query needed).

Brands:
  GWB     → brandSlug=globalwebbuilders
  Emrills → brandSlug=emrills
  Dnova   → brandSlug=dnova

================================================================================
AUTH
================================================================================
Public routes: no token.
Protected routes: Header Authorization: Bearer <token> (from login response).

================================================================================
ALL ENDPOINTS — CUSTOMER PORTAL (YOUR APP)
================================================================================
Base: GET/POST {API}/customer-area/...

--- PUBLIC (no login) ---

GET  /resolve-brand
     Resolve brand from host or ?brandSlug — use on app load for theme/logo.

GET  /brand-config
     Same as resolve-brand — returns id, name, slug, portalTheme (logo, colors, support).

POST /login
     Customer sign-in. Body: { email, password }. Returns token + user.
     Add ?brandSlug=emrills (or x-customer-host) on local.

--- PROTECTED (Bearer token + brand on local) ---

GET  /me
     Logged-in customer profile and linked brand accounts.

GET  /stats
     Dashboard summary: order counts, total spent, offers, unread notifications, popups, announcements.

GET  /my-sales
     Legacy summary: accounts + sales + leads (optional; prefer /orders).

GET  /orders
     Full order list with status, price, products, progress per order.

GET  /orders/:saleId/progress
     Service progress for one order (label, percent, steps).

GET  /invoices
     Invoice-style list derived from orders (amount, date, status).

GET  /offers
     Active upsells and discounts for this customer.

GET  /announcements
     Active brand announcements (banner/news).

GET  /popups
     Promotional popups not yet dismissed by customer.

POST /popups/:popupId/dismiss
     Mark popup as dismissed so it does not show again.

GET  /notifications
     Notification feed from xCRM (title, body, read flag).

================================================================================
STATS RESPONSE SHAPE (GET /stats)
================================================================================
data.orders.total       — all orders
data.orders.active      — pending + converted
data.orders.pending     — pending count
data.orders.converted   — converted count
data.totalSpent         — sum of converted order prices
data.offers.total       — active offers count
data.notifications.unread — unread notification count
data.popups.visible     — popups to show on dashboard
data.announcements.active — active announcements count
data.recentOrder        — latest order summary or null

================================================================================
TYPICAL PAGE → API MAP
================================================================================
App load / layout     → GET /brand-config?brandSlug=emrills
Login page            → POST /login?brandSlug=emrills
Dashboard home        → GET /stats + GET /popups (show modal if visible > 0)
Profile               → GET /me
Orders page           → GET /orders
Order detail          → GET /orders/:saleId/progress
Invoices page         → GET /invoices
Offers page           → GET /offers
Notifications         → GET /notifications
Announcements bar     → GET /announcements

================================================================================
RESPONSE FORMAT
================================================================================
Success: { success: true, data: ... }
Error:   { success: false, message: "..." }

Login success also includes: { token, user: { id, firstname, lastname, email, brandId } }
